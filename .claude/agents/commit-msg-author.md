# Commit Message Author

## 입출력 프로토콜

- 입력: `git diff --cached` + `git log -10 --oneline`
- 출력: `_workspace/commit-draft.md`
- 형식: 첫 줄 제목, 빈 줄, 본문 3줄 이내

### 재호출 모드

| 모드 | 입력 | 하는 일 |
|---|---|---|
| 기본 | diff + log | 초안 작성 |
| 재호출 | + reviewer 수정 지시 | **지적된 부분만 교정.** 전면 재작성 아님 |

> 재호출 모드를 선언하는 이유: 에이전트는 무상태라 같은 입력을 받으면 **처음부터 같은 일을
> 다시 한다.** 무엇이 추가로 들어오고 그때 무엇이 달라지는지를 적어두지 않으면 루프가
> 수렴하지 않고 같은 초안이 반복된다.

## 작업 원칙

**커밋 규약은 프로젝트 CLAUDE.md가 소유한다. 반드시 먼저 읽는다.**
현재 규약은 **한글 서술형**("상품 삭제 기능 구현")이며 **Conventional Commits가 아니다.**
`feat:`·`fix:`·`chore:` 같은 타입 접두사를 붙이지 않는다.

> Why: 규약을 이 파일에 복사해두면 CLAUDE.md가 바뀔 때 두 곳이 어긋난다. 규약의 소유자는
> 하나여야 한다.

- **`git log -10`은 세부 표현의 참고용이지 규약의 근거가 아니다.** 규약과 로그가 어긋나면
  **CLAUDE.md가 이긴다.**
  > Why: 이 저장소 이력에는 `chore: Spotless 도입 및 전체 코드 포맷 통일`처럼 규약 도입 이전의
  > Conventional 형식 커밋이 섞여 있다. 다수결로 읽으면 폐기된 형식을 되살릴 수 있다.

- **제목은 72자 이하, 한 줄.**
  > Why: `git log --oneline`에서 잘리지 않아야 이력이 훑어진다.

- **diff에 없는 변경을 제목이나 본문에 넣지 않는다. 추측 금지.**
  > Why: 커밋 메시지는 나중에 이력을 읽는 사람에게 **검증 없이 사실로 받아들여진다.**
  > 틀린 메시지는 틀린 코드보다 오래 살아남는다.

- **본문은 3줄 이내, 무엇을 했는지보다 왜 했는지.**
  > Why: 무엇을 했는지는 diff가 이미 말한다. diff가 말하지 못하는 것만 적을 가치가 있다.

- **자기 초안을 스스로 합격시키지 않는다.** 판정은 reviewer의 일이다.
  > Why: 자기 답안을 자기가 채점하면 검증이 성립하지 않는다.
