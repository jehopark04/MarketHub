# /polish

커밋 직전 정리 하네스. 오케스트레이터는 이 스킬이고 **판정·분기·복구·상태관리를 전부 여기서 한다.**
에이전트는 판단만 한다 — 다음 단계가 뭔지, 몇 번째 재시도인지 알려주지 않는다.

**사용자에게 묻는 지점은 [8] 하나뿐이다.** 다른 단계에서 확인을 구하지 않는다.

## 고정 명령 형태

아래 형태로만 호출한다. 형태가 고정돼야 권한 allowlist를 정확 일치로 좁힐 수 있고,
출력이 안정돼 [6]의 대조가 흔들리지 않는다.

| 용도 | 명령 |
|---|---|
| 작업공간 | `mkdir -p _workspace` |
| 범위 확정 | `git add -A` |
| 변경 유무 | `git diff --cached --quiet` (exit 0 = 변경 없음) |
| 포맷 | `./gradlew spotlessApply --console=plain` |
| 테스트 | `./gradlew test --console=plain` |
| 실패 클래스 추리기 | `grep -l "<failure\|<error" build/test-results/test/*.xml` |
| 체크포인트 | `git stash create` |
| diff 통계 | `git diff --cached --stat` |
| 커밋 | `git commit -F _workspace/commit-draft.md` |
| 복원 (1) 수정·삭제 원복 | `git checkout <SHA> -- .` |
| 복원 (2) 생성 원복 | `git clean -fd` |

## 테스트 결과 판독 규칙

[2]와 [6]이 공유한다. **순서를 지킬 것 — exit code가 먼저다.**

1. **exit 0** → 실패 없음. 끝.
2. **exit ≠ 0 이고 콘솔에 `:compileJava` 또는 `:compileTestJava` 실패** → **컴파일 실패**.
   XML을 읽지 말 것.
3. **exit ≠ 0, 그 외** → 테스트 실패.
   `grep -l "<failure\|<error" build/test-results/test/*.xml`로 실패 클래스를 추리고,
   **그 파일만** Read해서 실패한 `testcase`의 `classname`·`name`과 실패 메시지를 뽑는다.

> ⚠️ **XML을 먼저 보면 안 되는 이유**: 컴파일이 실패하면 gradle이 test 태스크를 아예 안 돌려서
> **이전 실행의 XML이 그대로 남는다.** 그걸 읽으면 "전부 통과"로 오독한다.
> exit code만이 이번 실행의 사실이다.
>
> 전부 통과일 때 XML을 안 읽는 이유: 7개 파일을 매번 읽으면 컨텍스트만 먹는다.
> `grep -l`이 아무것도 출력하지 않으면 그대로 "(없음)"이다.

## Workflow

### [0] 입력 게이트
1. `mkdir -p _workspace`
2. `git add -A`
3. `git diff --cached --quiet` → **exit 0(변경 없음)이면 [E0]**.
   화면에 "정리할 변경이 없습니다"만 출력하고 종료. 산출물 없음.
4. 작업 범위 = 인덱스. **이후 모든 단계는 `git diff --cached`만 취급한다.**

> add가 판정보다 먼저인 이유: `git diff`는 untracked 신규 파일을 보고하지 않는다.
> 신규 클래스만 만든 변경이 "변경 없음"으로 오판되고, 기존 수정과 섞이면 신규 파일이
> 작업 범위에서 조용히 누락된다.

### [1] 결정론적 정리
`./gradlew spotlessApply --console=plain`

이 단계는 베이스라인보다 앞이라 **하네스가 검증하지 않는 구간**이다. 결정론적이고 실패 시
컴파일로 즉시 드러나는 것만 둔다. 판단이 들어가는 도구를 여기 추가하지 말 것.

### [2] 베이스라인 기록
`./gradlew test --console=plain` → 위 **판독 규칙**대로 실패 목록을 얻는다.
**컴파일 실패면 [E5].** 그 외에는 실패 목록을 `_workspace/test-baseline.md`에 기록(덮어씀).

> 이 시점의 실패 = clean-coder 책임이 아님을 확정하는 근거다. [6]이 이걸 빼고 센다.
>
> **전제: 컴파일되는 트리에서만 호출된다.** 코드 작성·변경을 사용자 또는 다른 세션이 끝낸 뒤
> 검증을 맡기는 절차라, 베이스라인 컴파일 실패는 정상 흐름에 없다. 그럼에도 나오면 전제
> 위반이므로 즉시 [E5] — 컴파일 에러를 그대로 출력하고 종료한다. 여기서 안 멈추면 베이스라인이
> 테스트 목록이 아니게 되어 [6]의 뺄셈이 성립하지 않고, [6]은 그 컴파일 실패를 clean-coder가
> 만든 뒤집힘으로 오인해 헛돌이 2회 뒤 [E2]로 죽는다. 화면에는 "정리 실패"만 남고 진짜 원인은
> 어디에도 안 적힌다.
>
> 이 전제는 [2]에만 적용된다. **[6]의 컴파일 실패는 clean-coder가 직접 만든 것이라 실재하는
> 경로다** — 판독 규칙 2번은 전제와 무관하게 계속 필요하다.

### [3] 리뷰
`code-reviewer` 에이전트 호출.
- 입력: `git diff --cached` 출력 + `_workspace/test-baseline.md`
- 출력: `_workspace/review-report.md`

**리포트 파싱 계약** — 등급의 *정의*는 `code-reviewer.md`가 소유한다. 이 스킬은 **세기만 한다.**

- 고정 헤딩 세 개: `## A등급` / `## B등급` / `## 정보성`
- 각 항목은 `- `로 시작하는 최상위 불릿 하나. 해당 없으면 본문에 `(없음)`
- 분류는 정확히 이 셋이다. 넷째가 필요해지면 **SKILL.md 분기부터** 고쳐야 한다
- **B등급 항목에만 `- [B1] ` 형태의 태그가 붙는다.** 등장 순서대로, 결번·중복 없이.
  순서에 의미는 없다 — [6]이 항목을 지목하는 이름표다. A등급·정보성엔 붙지 않는다

> **정의를 여기 복사하지 않는 이유**: 세는 데는 "무엇이 A인가"가 필요 없다. 기준을 여기 적으면
> 오케스트레이터가 세는 대신 **재심**을 시작한다 — "이건 A로 매겨졌는데 B 같은데". 확률적 판정을
> 에이전트에 격리해둔 설계가 그 지점에서 풀린다. 두 벌이 어긋나는 문제는 덤이다.
>
> ⚠️ **헤딩 이름은 code-reviewer.md와의 계약이다.** 리포트가 `## A (중대)` 같은 다른 이름으로
> 나오면 세는 쪽이 **0건으로 읽고 그냥 통과시킨다** — 버그 리포트가 있는데도 [E1]이 안 걸린다.
> 한쪽만 고치면 조용히 깨지므로 항상 양쪽을 함께 고친다.
>
> **`[BN]` 태그도 같은 급의 계약이다.** 태그가 사라지면 [6]의 재시도 지시가 항목을 지목할
> 이름을 잃는다. 이쪽은 [3]에서는 조용하고 회귀가 났을 때만 터진다.

**분기는 위에서부터 먼저 맞는 것:**

- **A ≥ 1 → [E1]** — 화면에 "A등급 N건" 요약 + `review-report.md` 위치. 소스 미변경이라 복원 없음
- **B ≥ 1 → [4]**
- **A·B 전부 0 → [7] 직행** — 정리할 게 없으므로 clean-coder를 빈손으로 부르지 않는다

> `## 정보성`은 분기에 쓰이지 않는다. 테스트 파일 지적처럼 등급 밖 항목이 담기고,
> **[8]의 "미반영 항목"이 이걸 읽는다.** 소비자가 [3]이 아니라 [8]이라 여기서는 세지 않는다.

### [4] 체크포인트 (CP-CLEAN)
1. `git stash create` → 출력된 SHA를 받는다
2. **SHA를 `_workspace/checkpoint.txt`에 쓴다**

> SHA를 대화 컨텍스트에만 들고 있으면 안 된다. [5] 에이전트가 긴 출력을 반환한 뒤 40자리 hex
> 한 글자가 어긋나면 [E2] 복구가 통째로 실패한다. 강제 중단 뒤 사용자가 수동 복구할 재료이기도 하다.
>
> `git stash`(= push)를 쓰면 안 된다 — 워킹 트리에서 변경을 걷어내 [5]가 정리할 대상이 사라진다.

### [5] 정리 적용
`clean-coder` 에이전트 호출.
- 입력: `review-report.md`의 **B등급 항목만**(`[BN]` 태그를 떼지 말고 그대로 넘긴다).
  베이스라인은 주지 않는다(need-to-know)
- 출력: 워킹 트리 소스 수정

### [6] 회귀 검증
`./gradlew test --console=plain` → 위 **판독 규칙**대로 이번 실패 목록을 얻는다.

- **컴파일 실패 = 뒤집힘 전체로 센다.** 0건이 아니다.
  테스트가 하나도 안 돈 것을 "실패 0건"으로 읽으면 깨진 빌드가 그대로 커밋된다.
- 그 외 → **뒤집힘 = (이번 실패) − (베이스라인 실패)**

분기:
- **0건 → [7]**
- **≥1건 & 회귀재시도 < 2** → 회귀재시도 +1. 뒤집힌 테스트 정보를 **작업 지시로 번역해** [5] 재호출
- **≥1건 & 회귀재시도 = 2 → [E2]** — `checkpoint.txt`의 SHA로 **두 명령을 순서대로** 실행해
  체크포인트 시점 트리로 되돌린 뒤, 실패 리포트를 화면에
  1. `git checkout <SHA> -- .` — 체크포인트에 **있던** 파일을 그때 내용으로 (수정·삭제 원복)
  2. `git clean -fd` — 체크포인트에 **없던** 파일을 삭제 (생성 원복)

> **두 명령이 다 필요한 이유**: `checkout <SHA> -- .`는 "SHA에 있는 파일을 SHA 상태로 덮어쓴다"라
> [5]에서 새로 생긴 파일은 덮어쓸 대상 자체가 아니라 손이 안 닿는다. 그것만 쓰면 트리가
> `[5] 이전`이 아니라 `[5] 이전 + 고아 신규 파일`이 된다. "중복 로직을 클래스로 추출" 같은
> B등급 정리는 실제로 파일을 만든다.
>
> 고아 파일은 untracked라 E2 직후엔 조용하지만, **다음 실행 [0]의 `git add -A`가 아무 표시 없이
> 인덱스에 담아** 무관한 커밋에 섞인다. 지연 발화형이라 원인 추적이 어렵다.
>
> ⚠️ **`git clean -fd`의 안전성은 [0]의 `git add -A`에 의존한다.** clean은 untracked 파일을
> 가리지 않고 지우는데, [0]이 실행 시점의 모든 파일을 tracked로 만들어둔 덕에 E2에서 untracked인
> 것은 반드시 [0] 이후 = 에이전트가 만든 것뿐이다. **[0]의 `add -A`를 걷어내면 이 안전성도 함께
> 깨진다.** `-x`는 붙이지 않는다 — `build/`와 `_workspace/`는 남아야 한다.

> 번역이 스킬의 일인 이유: clean-coder는 베이스라인을 모른다. "X 테스트가 뒤집혔다"는 판정
> 데이터를 "`[B2]` 항목 수정이 원인일 수 있으니 그 부분만 교정하거나 되돌려라"는 지시로 바꿔야 한다.
>
> ⚠️ **항목은 리포트의 `[BN]` 태그로 지목한다. `파일:줄`로 지목하지 않는다.**
> 리포트는 [3]에서 한 번 쓰이고 이 루프 내내 얼어 있는데 **소스는 [5]가 계속 바꾼다.**
> 앞 항목을 적용한 순간 아래쪽 줄 번호가 밀려 리포트의 좌표가 실제 파일과 어긋나고,
> 재시도 2회면 두 번 밀린다. clean-coder가 그 줄을 열면 리포트가 말한 코드가 거기 없다.
> 태그는 리포트 안의 인덱스라 움직이지 않고, B만 발췌해 넘겨도 항목에 붙어 따라간다.
>
> 순번을 세어 "2번 항목"이라 부르지도 마라. 너는 리포트 전체를 보지만 clean-coder는
> 발췌된 B 목록만 받는다 — 세는 기준이 달라지면 같은 번호가 다른 항목을 가리킨다.

### [7] 커밋 메시지 생성
1. **진입부에서 `git add -A`** — [1] 포맷과 [5] 정리 결과를 인덱스에 동기화
2. `commit-message` 스킬 호출

**반환 계약**: 반환 텍스트의 **마지막 줄**이 `판정: PASS` 또는 `판정: FAIL`이다. [8]은 이 값만 본다.
하위 스킬 산출물은 `_workspace/commit-draft.md`(메시지)와 `_workspace/commit-review.md`(판정).
**`review-report.md`는 [3]의 것이므로 하위 스킬이 건드리지 않는다.**

> [6] 통과와 [3] 직행 두 경로가 여기로 들어온다. add를 [6] 안에 두면 직행 경로가 스테이지
> 안 된 채 도착해 하위 스킬이 precondition에서 죽는다.
>
> 하위 스킬의 내부 author↔reviewer 루프는 들여다보지 않는다. 반환값만 취급한다.

### [8] 사용자 게이트

**`판정: FAIL` 반환** — 반영/미반영 항목 + `git diff --cached --stat` +
"커밋 메시지 자동 검증 실패 - 수동 확인 필요"를 출력하고 **[E4]**.
승인 절차 없이 종료한다 — 검증하지 못한 메시지로 커밋하지 않는다.
워킹 트리는 스테이지된 채 남으므로 사용자가 직접 커밋하면 된다.

**`판정: PASS` 반환** — 승인용 요약을 출력하고 승인을 구한다.
- 승인 → `git commit -F _workspace/commit-draft.md` (로컬까지. **푸시하지 않는다**)
- 미승인 → **[E4]** 워킹 트리 유지, 커밋만 안 함

## 종료 경로

| 코드 | 조건 | 워킹 트리 |
|---|---|---|
| E0 | 변경 없음 ([0]) | 그대로 |
| E1 | A등급 ≥ 1 ([3]) | 미변경 |
| E2 | 회귀 2회 복구 실패 ([6]) | 체크포인트 시점으로 복원 (`checkout` + `clean -fd`) |
| E3 | **없음** — 아래 주석 참조 | — |
| E4 | 메시지 검증 실패 또는 미승인 ([8]) | 스테이지된 채 유지 |
| E5 | 베이스라인 컴파일 실패 = 전제 위반 ([2]) | 그대로 (clean-coder 미실행) |

> **[E3]은 없다.** 테스트 수렴 실패 경로였는데 test-writer를 하네스에서 빼면서 T루프와 함께
> 제거됐다. **라벨은 이름이지 순번이 아니라 재배열하지 않는다** — E4를 E3으로 당기면 이 문서
> 바깥의 참조(과거 실행 리포트, 설계 노트, 사용자 기억)가 조용히 어긋난다.
> 이 자리는 닫힌 자리다. 새 종료 코드를 E3에 채우지 말고 E5부터 쓴다.

## 모든 종료 경로 공통

- **`git reset`을 하지 않는다.** [0]에서 스테이징한 상태 그대로 종료한다. 사용자의 사전
  스테이징 선택을 파괴하는데 워킹 트리 내용은 온전하므로, 해제가 복구가 아니라 손실이다.
  **[E4]의 "미커밋"은 "언스테이지"가 아니다.**
- 체크포인트를 따로 정리하지 않는다. `git stash create`가 만든 dangling 객체는 git이 회수한다.
- `_workspace/` 산출물은 남긴다. 다음 실행이 덮어쓴다.

## 산출물 형식

### `_workspace/test-baseline.md`
식별자는 XML의 `classname` + `name`. 이 프로젝트는 `@DisplayName`을 쓰므로
`name`에 메서드명이 아니라 **한글 문장**이 들어간다.

```
# 베이스라인 (YYYY-MM-DD HH:MM)

## 실패한 테스트
(없음)
```
실패가 있으면:
```
## 실패한 테스트
- used.system.product.ProductServiceImplTest
  「본인 상품을 수정하면 값이 변경된다」
  기대: 제목이 "새제목"으로 변경됨
  실제: AssertionFailedError — expected "새제목" but was "옛제목"
```

**통과 목록은 적지 않는다.** [6]의 계산이 `이번 실패 − 베이스라인 실패`라 통과 목록이
쓰이지 않는다. XML에 통과 결과도 다 있지만 **소비자 없는 데이터는 적지 않는다.**

### `_workspace/checkpoint.txt`
SHA 한 줄만. 사람이 수동 복구할 때 그대로 붙여넣을 수 있어야 한다:

```
git checkout <SHA> -- .   # 수정·삭제 원복
git clean -fd             # 생성 원복
```

### 승인용 요약 (화면)
1. **반영된 항목** — B등급 중 실제로 적용된 것
2. **미반영 항목** — 테스트 파일 지적 등 등급 밖 정보성 항목
3. `git diff --cached --stat` 결과
4. 커밋 메시지 (PASS일 때)

## 카운터
- **회귀재시도** — [6]에서만 증가. 최대 2. 이 스킬이 관리한다.
- 에이전트에게 회차를 알려주지 않는다. 무상태라 알 수 없고, 알 필요도 없다.
